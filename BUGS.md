# Дефекты API стенда

Расхождения между поведением `https://qa-internship.avito.com` и ожиданиями из [TESTCASES.md](TESTCASES.md). Соответствующие автотесты помечены `pytest.mark.xfail` (где применимо) или обходятся в коде до исправления API.

После исправления на стенде снимите `xfail` и перепроверьте `pytest`. Для дефекта успешного POST (BUG-004) после исправления контракта можно убрать обход через дополнительный GET в `domain.create_item`.

---

## BUG-001

**Краткое описание:** Для ответов HTTP 404 форма поля `result` на стенде может отличаться от примеров в Postman (строка vs объект с вложенными полями), что усложняет единый парсинг на клиенте.

**Шаги воспроизведения:**

1. Выполнить `GET https://qa-internship.avito.com/api/1/item/{несуществующий_uuid}` с заголовком `Accept: application/json`, подставив валидный UUID v4, для которого объявления нет.
2. Просмотреть JSON тела ответа и тип/структуру поля `result`.

**Фактический результат:** Тело 404 приходит в одном из вариантов (например, `result` как объект с полем `message` или иная схема), не всегда совпадая с «строковым» примером из коллекции.

**Ожидаемый результат:** Задокументированная и стабильная схема JSON для всех GET-ручек с кодом 404; клиенты могут полагаться на один формат.

**Серьёзность:** Minor

**Окружение:** Публичный стенд `https://qa-internship.avito.com`; клиент: браузер/Postman/curl или автотесты на Python (`requests`).

## BUG-002

**Краткое описание:** Для `GET /api/1/{sellerID}/item` при `sellerID = 0` и отрицательных значениях path-параметра стенд не возвращает ожидаемую ошибку валидации 400.

**Шаги воспроизведения:**

1. `GET https://qa-internship.avito.com/api/1/0/item` с `Accept: application/json`.
2. `GET https://qa-internship.avito.com/api/1/-1/item` с `Accept: application/json`.

**Фактический результат:** Для `0` — HTTP 200 и пустой массив `[]`. Для `-1` — HTTP 200 и JSON-массив с объявлениями (не соответствующий ожидаемой валидации идентификатора продавца).

**Ожидаемый результат:** HTTP 400; в теле ошибки есть текст, содержащий «передан некорректный идентификатор продавца» (как в [TESTCASES.md](TESTCASES.md), кейсы GET-AI-004, GET-AI-005).

**Серьёзность:** Major

**Окружение:** Публичный стенд `https://qa-internship.avito.com`; автотесты: `get_ai_tests.py` (GET-AI-004, GET-AI-005).

## BUG-003

**Краткое описание:** Создание объявления отклоняется с HTTP 400 при нижней границе `sellerID = 111111` и/или при нулевых значениях всех полей в `statistics`, хотя по тест-дизайну в TESTCASES эти значения допустимы.

**Шаги воспроизведения:**

1. `POST https://qa-internship.avito.com/api/1/item` с телом из сценария POST-002 (`sellerID`: 111111, остальные поля валидны), заголовки `Content-Type: application/json`, `Accept: application/json`.
2. `POST` с телом из сценария POST-005 (`statistics.likes`, `viewCount`, `contacts` равны 0).

**Фактический результат:** HTTP 400 Bad Request вместо успешного создания.

**Ожидаемый результат:** HTTP 200; создано объявление; в ответе (или при последующем GET по `id`) данные согласованы с телом запроса.

**Серьёзность:** Major

**Окружение:** Публичный стенд `https://qa-internship.avito.com`; автотесты: POST-002, POST-005 в `post_tests.py`.

## BUG-004

**Краткое описание:** При успешном `POST /api/1/item` тело ответа часто не соответствует полной схеме объявления (`id`, `sellerId`, `name`, `price`, `statistics`, `createdAt`), а выглядит как укороченное сообщение со строкой статуса/UUID; автотесты извлекают `id` и догружают данные через `GET /api/1/item/{id}`.

**Шаги воспроизведения:**

1. Выполнить валидный `POST https://qa-internship.avito.com/api/1/item` (как в POST-001).
2. Сравнить тело ответа со схемой полного объявления из контракта/модели `ItemResponse` в проекте.

**Фактический результат:** HTTP 200, но JSON не проходит валидацию как полный `ItemResponse` (неполный набор полей или иная структура).

**Ожидаемый результат:** HTTP 200 и JSON с полями `id`, `sellerId`, `name`, `price`, `statistics`, `createdAt` в соответствии с ожидаемым контрактом создания.

**Серьёзность:** Major

**Окружение:** Публичный стенд `https://qa-internship.avito.com`; логика обхода: `domain.ItemDomain.create_item`, `helpers.extract_item_id_from_malformed_post_success`; тест POST-001 (при необходимости помечен `xfail` до выравнивания контракта).

## BUG-005

**Краткое описание:** Для части невалидных тел `POST /api/1/item` стенд возвращает не тот текст в `message`, отдаёт HTTP 200 вместо 400 или сообщение не содержит ожидаемой подстроки из TESTCASES.

**Шаги воспроизведения:**

1. Выполнить `POST /api/1/item` с телами из параметризации негативных кейсов POST-010, POST-016–POST-030 в `post_tests.py` (`_neg_params`).

**Фактический результат:** Несовпадение с проверками `assert_json_error_400` и/или HTTP 200 с телом вида «Сохранили объявление …» при данных, которые по спецификации должны отклоняться.

**Ожидаемый результат:** HTTP 400 и тексты ошибок в духе TESTCASES для каждого типа нарушения (обязательные поля, типы, знак, целочисленность и т.д.).

**Серьёзность:** Major (до Critical при ложном успехе на явно невалидных данных)

**Окружение:** Публичный стенд `https://qa-internship.avito.com`; Windows/Linux/macOS; Python, `pytest`, `post_tests.py`.

## BUG-006

**Краткое описание:** При синтаксически неверном JSON в теле `POST /api/1/item` сообщение об ошибке не содержит ожидаемой подстроки «Передан не валидный JSON» (или эквивалента), на который ориентируется тест POST-031.

**Шаги воспроизведения:**

1. Отправить `POST https://qa-internship.avito.com/api/1/item` с `Content-Type: application/json` и телом с синтаксической ошибкой JSON (как в `test_post_031_invalid_json`).

**Фактический результат:** HTTP 400 возможен, но текст/структура ошибки не проходит проверку теста на наличие ожидаемой формулировки.

**Ожидаемый результат:** HTTP 400 и сообщение, согласованное с TESTCASES (подстрока про невалидный JSON).

**Серьёзность:** Minor / Major

**Окружение:** Публичный стенд `https://qa-internship.avito.com`; автотест POST-031.

## BUG-007

**Краткое описание:** При `POST` с недопустимым `Content-Type` (например, `text/plain`) при JSON-теле ответ 400 может иметь структуру, отличающуюся от ожидаемой модели ошибки (`messages`: null и т.п.), из-за чего строгая валидация в тесте падает.

**Шаги воспроизведения:**

1. Выполнить `POST https://qa-internship.avito.com/api/1/item` с заголовком `Content-Type: text/plain`, `Accept: application/json`, и валидным JSON в теле (как в `test_post_032_wrong_content_type`).

**Фактический результат:** HTTP 400 возможен, но тело не всегда соответствует ожидаемой схеме `ErrorResponse400`; сообщение может не содержать «Недопустимый тип контента» в проверяемом виде.

**Ожидаемый результат:** Стабильный контракт тела ошибки; в сообщении присутствует текст про недопустимый тип контента (по TESTCASES).

**Серьёзность:** Major

**Окружение:** Публичный стенд `https://qa-internship.avito.com`; автотест POST-032.

## BUG-008

**Краткое описание:** При `sellerID` вне диапазона 111111–999999 ответ не содержит ожидаемого текста про допустимый диапазон; в сообщении может фигурировать другое поле (например, про `likes`).

**Шаги воспроизведения:**

1. `POST https://qa-internship.avito.com/api/1/item` с `sellerID`: 111110 (POST-035).
2. `POST` с `sellerID`: 1000000 (POST-036), остальные поля валидны.

**Фактический результат:** Сообщение об ошибке не совпадает с ожидаемым фрагментом про диапазон `sellerID`.

**Ожидаемый результат:** HTTP 400; в `message` (или эквиваленте) явно указано требование диапазона `111111–999999` для `sellerID`, как в TESTCASES.

**Серьёзность:** Major

**Окружение:** Публичный стенд `https://qa-internship.avito.com`; автотесты `test_post_035_seller_below_range`, `test_post_036_seller_above_range`.

## BUG-009

**Краткое описание:** Для невалидного `id` (не UUID) `GET /api/1/statistic/{id}` возвращает HTTP 400, а `GET /api/2/statistic/{id}` — иной код (например, 404) при схожем по смыслу сценарии валидации.

**Шаги воспроизведения:**

1. `GET https://qa-internship.avito.com/api/1/statistic/123456` с `Accept: application/json`.
2. `GET https://qa-internship.avito.com/api/2/statistic/123456` с `Accept: application/json`.

**Фактический результат:** Различие HTTP-кодов и/или структуры ответа между v1 и v2 при одной и той же ошибке формата идентификатора.

**Ожидаемый результат:** Единообразные коды и тела для ошибки валидации идентификатора в обеих версиях (предпочтительно HTTP 400).

**Серьёзность:** Minor / Major

**Окружение:** Публичный стенд `https://qa-internship.avito.com`; автотест GET-STAT-006 (`get_statistic_tests.py`), фиксирующий фактическое поведение v2.
